# 新品上市域业务语义卡（业务文档编译）

> 出处：`docs/新品上市业务背景与功能说明.md`（飞书 wiki 2026-10-23 拉取）。
> 本卡只载**元数据查不到的业务语义**（业务链、齐套含义、判定链、决策枚举、编码字典、关键规则公式口径）；
> 实体/属性/关系清单与实例规模一律以 `metadata_list_*` 与 `objects_query` 实时返回为准——本卡不维护元数据副本、不快照数据实态，规则明细以 `metadata_list_rules` 实时清单为准。

## 业务链总览（五大模块）

```
新品分型 → 新品需求 → 六类齐套 → 首批采购 → 上市前保障
 参考品绑定   周粒度预测需求   倒排+状态判断   物料齐套计算+方案   齐套状态+到货跟踪
```

计划时间范围：以计划上市日 **T** 为基准，默认 **T-28 至 T+28**（可配置参数）。

## 六类齐套（ReadinessUnit）业务含义与上游约束

| 齐套单元 | 工作范围 | 上游约束（业务文档口径） |
| --- | --- | --- |
| 商品齐套 | 商品基础信息、销售规格及上市范围等准备 | 无 |
| 配方齐套 | BOM 配方及冻结/发布准备 | 无 |
| 仓配齐套 | 门店与上游供应仓库覆盖关系确认 | 无 |
| 物料齐套 | 基于预测需求、BOM、库存及在途计算物料齐套时间与数量 | 商品、配方、仓配齐套、门店与营销齐套 |
| 供应齐套 | 供应商向仓库交付及到仓可用保障 | 物料齐套 |
| 门店与营销齐套 | 门店上架、设备及培训等已定义准备情况 | 商品齐套 |

- **状态判断链语义**：时间轴滚动 → 子齐套项状态判断规则 → SubReadinessUnit.readiness_status → 齐套单元状态判断规则 → ReadinessUnit.readiness_status（规则明确：**所有子齐套项均齐套，齐套单元才视为齐套**）→ 计划通过状态 → NewDishLaunchPlan.plan_status（完整判断分支未定义，枚举现查）。
- **时间倒排语义**：从 NewDishLaunchPlan.planned_ready_date 倒推六类的 max_readiness_start_date / max_readiness_end_date；子项排期（plan_readiness_start/end_date、operator_code 负责人）由业务人员安排，子项自动倒排规则本体未定义。
- 业务文档的上游约束表与实例依赖边存在出入（自指、缺边等）——**溯源以实例 `upstream/downstream_readiness_unit_list` 为准**，差异列待业务确认（模式见 facts.md 数据侧行为）。

## 上市决策与风险台账

- **上市决策枚举**：**通过 / 有条件通过 / 延期**（上市风险实体定义，六类齐套整体检查结果支撑上市决策）——回答「能否上市」以此组织档位，结合风险台账 open 风险，不替业务拍板。
- 上市风险实体是**齐套诊断的现成问题台账**：risk_category（按期上市风险）/ risk_type（对应齐套域）/ 关联触发单元与子项 / risk_status / risk_owner / mitigation_plan——处理顺序表直接引用，台账未覆盖处如实注明。
- 就绪日存在**双口径可能**（计划表 planned_ready_date 与齐套层 planned_ready_date）——并存时如实列出，待业务确认统一。

## 关键规则公式口径（引用数值时的口径依据）

- 物料净需求 = 毛需求 − 总齐套量（派生属性，回写与否现查，未回写时按此公式做展示层计算并注明）。
- 优化后缺货量 = MAX(0, 预测需求 − 满足量)；优化后缺货成本 = 缺货量 × 单位成本；采购计划的采购成本 = 计划总量 × 单位成本（成本规则已建，可读回写值）。
- 齐套环节计划/实际开始时间 = 子齐套最早值；结束时间 = 最晚值。
- 预测新品首月均店销量 = 上市实际均店销量 × 季节 × 价格 × 门店 × 营销费用系数；首月需求预测基准值与首月经营目标为**不同源口径**（口径三分离见 SKILL.md 铁律）。
- 标注【待处理】的规则（价格系数/营销费用系数/齐套与子齐套状态触发/计划起止日期等）引用时必须注明，实例可能已有回写值（双标注）。业务文档规则名与实测规则名不一一对应，以实测为准。

## 域内编码字典（本体设计常量）

- 六类单元：Q0001 商品 / Q0002 配方 / Q0003 物料 / Q0004 供应 / Q0005 仓配 / Q0006 门店与营销；`readiness_status` 中文枚举「已齐套 / 未齐套」。
- 子项命名：`SQ{单元编码4位}_{序号2位}`；**`sub_readiness_desc` 是每条子项判定口径的原文**——回答「为什么没齐套/判定依据」的第一来源，直接引用。
- 计划状态区分历史/进行中看 plan_status 实时值（枚举经历过中文化变更，不硬编码英文旧值）。
