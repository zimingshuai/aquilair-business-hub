# X20 沙箱推演 POC 演示脚本（完整版）

> 适用版本：model v0.3.0-draft.3（20 实体）/ 函数 9 个 / 演示数据 72 行（已导入平台）。
> 演示总时长约 25–30 分钟（含讲解）；核心高光在第三部分"四沙箱对比"。
> 每步标注：【操作】= 演示者在平台上做什么；【画面】= 观众看到什么；【讲】= 讲解话术要点。

## 演示前准备（一次性，演示前完成）

1. 平台导入 studio-model.yaml（20 实体）→ create_workspace 建表 → 导入 72 行基础数据（demo-data-edits.json）；
2. 录入 9 个函数（bom_check_diff / impact_scope / bom_explode / supply_demand_allocation / substitute_fill / risk_identify / strategy_simulate / scheme_compose / purchase_plan_generate），并配 6 个动作引用；
3. 策略库 2 行启用（STRAT-SUB 替代消耗 P1 / STRAT-PURCHASE 采购建议 P2；取消采购/延期到货等处置类策略当前不入基线，需要时加行即可）；
4. 平台侧准备 4 个沙箱（复制生产数据）：2×2 决策矩阵 = 替代路径（use_substitute 参数注入）× 缺口采购（沙箱内策略库开关），详见步骤 3。

## 第一部分：变化感知——BOM 点检（main 真实环境）

### 步骤 1｜执行 BOM 点检

【操作】调用 bom_check_diff，参数：基准版 BOM-X20-V1、目标版 BOM-X20-V2、批次号 CHK-X20-20261022-01。
【画面】点检批次 1 条 + 差异清单 7 条：

| 物料 | 差异类型 | 内容 |
|---|---|---|
| LED-B1 光源模组 | 删除 | V1 有 V2 无 |
| MG-CASE 镁合金外壳 | 新增 | V2 新增，用量 1、损耗 2% |
| LENS-45 镜片 | 属性变更 | 用量 2→1.5（调低） |
| IC-M9771 主控芯片 | 属性变更 | 用量 1→2（调高） |
| FAN-40→FAN-40S | 替代新增 | 优先级 1、比例 1.0 |
| FAN-40→FAN-40A | 替代属性变更 | 优先级 1→2、比例 1.0→1.2 |
| CAP-100→CAP-100T | 替代删除 | 认证失效 |

【讲】研发升级了 X20 的 BOM：换光源方案、加金属外壳、镜片省料、芯片翻倍、风扇替代策略调整。系统自动比对两版正式计划 BOM，六类差异一次找齐——这是后面一切计算的起点，每条差异都可追溯到两版 BOM 的原始行。

### 步骤 2｜评估影响范围

【操作】调用 impact_scope，参数：批次号。
【画面】影响视图：变化物料 6 种 → 反查 BOM → 受影响成品 P-X20 → 已确认未交付订单 2 笔（SO-101 500 台 + SO-102 300 台 = 800 台）→ 影响等级**高**；繁杂度：净新增物料种类 1−1=0，**不上升**。
【讲】所有变化都落在 X20 一个产品上，800 台在手订单受影响。变化本身不可怕，可怕的是不知道它波及什么——现在波及范围清楚了。

## 第二部分：沙箱推演展开（平台建沙箱，假设注入）

### 步骤 3｜创建沙箱（平台后台）

【操作】平台创建 4 个沙箱（各自复制一份生产数据），决策假设两维：替代路径（use_substitute 参数：ALL/NONE）× 缺口采购（策略库 STRAT-PURCHASE 启停）：
- 沙箱1：用替代料（按优先级）+ 缺口采购
- 沙箱2：用替代料（按优先级）+ 缺口不采购
- 沙箱3：不用替代料 + 缺口采购
- 沙箱4：不用替代料 + 缺口不采购
【讲】从这一步开始进入沙箱推演：**每种决策组合一个沙箱**，每个沙箱都是生产数据的完整副本——推演再大胆，真实数据毫发无损。复制、隔离、对比由平台后台完成。沙箱间唯一变量是决策组合，策略库的启用基线在建沙箱前统一设定，四个沙箱继承同一套。

### 步骤 4｜（每个沙箱内）生成物料需求

【操作】在各沙箱内调用 bom_explode，参数：批次号。
【画面】每沙箱 9 行物料需求：根需求 800 台（两笔订单未交付合计）；FAN-40 毛需求 1680=800×2×1.05、CAP-100 3264、MG-CASE 816、IC-M9771 1616、LENS-45 1236、光机 800 及子件 816/840；LED-B1（删除料）目标版毛需求 0 专行保留。
【讲】多层 BOM 逐层展开、每层独立计损耗；删除的料留一行零需求——它的呆滞账在后面算。四个沙箱在这一步结果相同（毛需求只跟 BOM 和订单有关）。

### 步骤 5｜（每个沙箱内）供需分配

【操作】在各沙箱内调用 supply_demand_allocation。
【画面】供需分配账本 11 笔：FAN-40 需求 1680 ← 库存 800（FEFO：3 月批次 300 先分）→ 在途 PO 300，缺 580；MG-CASE 只有在途 700、缺 116；IC-M9771 缺 716……
【讲】"库存只能用一次"的账本机制：同一物料的全部需求行是竞争者，每笔分配记账（供方余量/需方余量）。

### 步骤 6｜（每个沙箱内，分岔点）替代料填补

【操作】各沙箱内调用 substitute_fill（沙箱假设经 use_substitute 参数注入）。
【画面】
- 沙箱1/2：FAN-40S 填 300（量少）→ FAN-40A 补剩余 280（比例 1.2，消耗 336）→ 缺口清零；
- 沙箱3/4：不填补，FAN-40 剩余缺口 580。
【讲】**分岔点**：同一个 580 的缺口，按沙箱假设给出不同解法。替代料的库存与成本差异（S 量少价高、A 量多价低）从这里开始影响每个世界。

### 步骤 7｜（每个沙箱内）风险识别

【操作】各沙箱内调用 risk_identify。
【画面】每沙箱 8 条风险（呆滞 6 + 缺口 2），替代料两行按沙箱不同：

| 风险 | 沙箱1/2（用替代） | 沙箱3/4（不替代） |
|---|---|---|
| LED-B1 BOM删除呆滞 | 350×85=29,750 | 同 |
| LED-B1 在途冗余 | 200×85=17,000 | 同 |
| LENS-45 用量减少呆滞 | 412×60=24,720 | 同 |
| LENS-45 在途冗余 | 300×60=18,000 | 同 |
| FAN-40S 呆滞 | 0（300 全消耗） | 300×30=9,000 |
| FAN-40A 呆滞 | 64×28=1,792 | 400×28=11,200 |
| MG-CASE 缺口（BOM新增） | 116×150=17,400 | 同 |
| IC-M9771 缺口（用量调高） | 808×120=96,960 | 同 |

【讲】风险清单因沙箱而异——用哪个替代料，剩下的呆滞完全不同。按 OQ-003 裁决不做等级评估，清单按数量/金额排序呈现。

### 步骤 8｜（每个沙箱内）策略测算 + 方案组合

【操作】调用 strategy_simulate → scheme_compose（沙箱3/4 的采购建议按沙箱开关启停）。
【画面】沙箱1/3 生成采购建议测算 5–6 条；沙箱2/4（不采购）无测算行——方案组合按**维持现状口径**照常产出，缺口/呆滞全额计入目标值。每沙箱按**优化目标目录**逐维度写入方案评估（SupplyDemandObjective 的 8 行维度：按期交付台数/延迟台数/剩余缺口数量/剩余呆滞数量/采购数量/采购金额/附带成本/预计周期）。

## 第三部分：对比与决策（高光时刻）

### 步骤 9｜四沙箱对比看板（目标目录驱动）

【画面】四套方案按目标目录逐维度并列：

| 目标维度（目录行） | 沙箱1 替代+采购 | 沙箱2 替代+不采购 | 沙箱3 不替代+采购 | 沙箱4 不替代+不采购 |
|---|---|---|---|---|
| 按期交付台数（台） | **800** | 446 | **800** | 446 |
| 延迟交付台数（台） | 0 | 354 | 0 | 354 |
| 剩余呆滞数量（个） | LED 550/LENS 712/40A 64 | 同左 | LED 550/LENS 712/**40S 300/40A 800** | 同左 |
| 剩余缺口数量（个） | 0 | **MG 116/IC 716/IC-DP 116/CAP 1264/LENS 336** | FAN-40 580 + 常规缺口 | FAN-40 580 + 全部 |
| 采购金额（元） | 135,020 | 0 | **150,100** | 0 |
| 附带成本（元） | 0 | 0 | 0 | 0 |

【讲】**这就是沙箱推演的价值**：同一份点检事实，四种决策组合走出四个世界——
- 不采购的世界：交付卡在 IC 芯片（446 台）、缺口全额暴露——**光换替代料救不了交期，芯片缺口必须采购**；
- 用替代 vs 不替代：呆滞差 1 万+、FAN-40 采购差 15,080——替代料"白拿"的价值清清楚楚；
- 每个数字可下钻到点检差异源头，每个沙箱的证据链独立完整。
**系统列事实，人拍板。**

（可选讲点：IC-DP/CAP-100 无供应商主数据 → 交期测算按乐观口径并告警——主数据完备性的价值顺带呈现。）

### 步骤 10｜选定沙箱，落地采购计划

【操作】决策人选定沙箱1 → 方案状态置"已选定" → 调用 purchase_plan_generate。
【画面】采购计划 5 条（待审批）：MG-CASE 116→SUP-MG、IC-M9771 716→SUP-IC、IC-DP 116（无主数据）、CAP-100 1264（无主数据）、LENS-45 336→SUP-OPT。
【讲】选定世界的采购计划一键生成、待审批。

### 步骤 11｜审批

【操作】计划状态 待审批 → 已下达（UI 直改，动作化后续增量）。
【讲】从 BOM 变化到采购下达，全链每一步都有对象留痕、可追溯、可审计。

## 收尾：本体价值总结（30 秒）

1. **变化可感知**：两版 BOM 六类差异自动找齐，影响范围反查到订单；
2. **后果可推演**：每种处置假设一个沙箱，各自完整走完计算链，互不污染；
3. **对比可量化**：四套方案并列，呆滞/缺口/采购/附带成本全维度呈现，且每个数字可下钻到点检差异源头；
4. **决策有留痕**：选定哪个沙箱、谁拍板、生成什么计划，全部对象化沉淀；
5. **维度可扩展**：新增处置方式（出售、报废、转替代……）= 策略库加一行数据，不改代码。

## 附：演示常见问题应答

- **"没有本体也能做吧？"**：算出三个世界的数字确实不需要本体——但每套方案的完整证据链（点检差异→需求行→分配账本→风险→策略）作为对象留存、可下钻可审计、假设即数据（新维度加一行策略）、多世界隔离由平台原生承载，这些用脚本要么做不出、要么要自建全套脚手架。
- **"风险为什么不分级？"**：2026-10-21 裁决（OQ-003）——不做等级评估，清单按金额排序呈现，分级是展示层的事。
- **"沙箱怎么做的？"**：平台后台能力——每个沙箱复制生产数据、隔离运行，对比由平台承载；模型和函数里没有一行沙箱代码。
- **"为什么没有取消采购/延期到货的测算行？"**：处置类策略（取消/延期/出售/报废）函数已实现、由策略库驱动；当前演示基线只启用 替代消耗 与 采购建议，需要时在策略库加一行数据即可（不改代码、即刻参与下一轮测算）。
