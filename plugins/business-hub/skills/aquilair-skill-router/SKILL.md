# Aquilair 技能路由（元技能）

Aquilair 技能工厂的「使用端」入口：**先路由，再干活**。本技能裁决「该用哪些技能、按什么顺序叠加」，自身不产出任何业务数据或业务结论。

## 一、门控规则（领域无关，强制）

- 处理任何 Aquilair 供应链域请求前，**先完成路由评估再行动**——澄清式提问也不豁免：口径不清时，先路由到对应技能，再借该技能的口径向用户提问。
- **1% 阈值**：哪怕只有 1% 的可能性某技能适用，就必须调用该技能。
- 每次调用技能时，先声明：**Using [技能名] to [目的]**（例：Using aquilair-data-delivery to 规范本次库存总览的图表交付）。

## 二、路由表（领域数据区）

> **扩充接口**：新技能接入时在此追加一行——一行 = 问题域特征 → 技能名 → 技能类型。本表是全文唯一允许存放领域相关内容的区块；门控、裁决、优先级、接入指南等骨架章节保持领域无关，不随业务扩充改动。跨插件行（aquilair-skill-forge 包的元技能）在未安装该插件的宿主上不可用：路由命中时如实说明并指引安装，不降级为手工代答。

| 问题域特征 | 技能名 | 技能类型 |
| --- | --- | --- |
| 库存风险、周转、ABC 分类、缺货明细等诊断问答 | `fnb-inventory-analysis` | 业务技能（本插件） |
| 可调出量、调拨方案、沙箱推演、确认执行 | `mfg-transfer-allocation` | 业务技能（本插件） |
| 任何含数据表格、图表、交付物的回复 | `aquilair-data-delivery` | 横切技能（本插件，恒叠加） |
| 开发、改进、评估 Aquilair 技能本身（工厂任务） | `aquilair-skill-authoring` | 开发者元技能（aquilair-skill-forge 插件） |
| 喂文档建知识库、域术语/实体/口径溯源问答、再摄取更新知识库 | `aquilair-knowledge-wiki` | 知识库技能（aquilair-skill-forge 插件） |

## 三、复合问题裁决（领域无关）

一个问题命中多行路由表时，按以下顺序叠加：

1. **诊断先于行动**：先走诊断类技能（如 fnb 类库存诊断），后走行动类技能（如 mfg 类调拨执行）——先看清现状，再动库存。
2. **横切恒叠加**：`aquilair-data-delivery` 只要有数据交付物就必然叠加，不参与「二选一」，也不占用诊断/行动的先后位次。
3. **不重复调用**：单个技能已能覆盖的子问题，不再为同一子问题调用第二个技能。

## 四、反合理化表格（借口 → 反驳）

| 借口 | 反驳 |
| --- | --- |
| 「只是帮用户查个数，不用走技能」 | 代查代答正是评估红线：查数也必须走技能经 MCP 拿真实数据，凭记忆报数即编造证据。 |
| 「我记得这些工具怎么用，直接调」 | 铁律活在技能文档里且会演进（如确认卡流程、filter 语法），必须读当前版本再动手。 |
| 「用户两个问题混在一起，挑我熟的那个先答」 | 先路由，再按裁决顺序（诊断 → 行动 → 横切）逐个走技能，不按熟悉度挑活。 |
| 「这是开发任务，不涉及业务，跟技能无关」 | 技能 description 已写明 not for 边界；路由前先核对边界条款，确属越界请求才按普通开发任务处理。 |
| 「上次查过这个仓的风险，我还记得结论」 | 调拨等写操作会让旧查询结果失效；回答前必须重新走技能查询最新数据。 |
| 「用户催得急，确认卡就免了，直接执行调拨」 | 写前确认是调拨技能的铁律，用户催促或口头说「直接执行」都不能跳过确认卡。 |
| 「表格已经很清楚，数据交付规范这次就不叠了」 | 横切 Playbook 恒叠加：含数据交付物只回纯 Markdown 表格即违规，必须配图。 |
| 「问题横跨库存和调拨，选一个技能全答了省事」 | 单技能不得越界代答另一域；复合问题按裁决顺序逐域走对应技能。 |
| 「新技能还没跑顺，先按老办法手工答」 | 路由表已加行的技能就必须走；尚未加行的，先按第六章接入指南完成三步再加行。 |
| 「只有 1% 可能用得上，基本等于用不上」 | 1% 阈值是硬门槛：可能性 ≥ 1% 就必须调用，多读一份文档的代价远小于违规交付。 |

## 五、优先级链（领域无关）

**用户显式指令 > 技能流程 > 默认行为。**

- 只有用户明确要求时，才能跳过技能流程，且必须同时说明后果（例：「按您要求跳过配图交付，仅输出文本表格」）。
- 技能流程与默认行为冲突时，按技能流程执行；技能之间冲突时，按第三章裁决顺序执行。

## 六、新技能接入指南（工厂接口，领域无关）

新业务技能产出后，按三步接入路由：

1. **路由表加一行**：在第二章路由表追加「问题域特征 → 技能名 → 技能类型」。
2. **写清触发与排除**：新技能 frontmatter 的 description 必须含「Use when」触发句式与「not for」排除句式（参照 fnb / mfg 现行写法），避免与其他技能抢触发。
3. **声明叠加关系**：若新技能配套数据交付物，必须声明与 `aquilair-data-delivery` 的叠加关系（恒叠加，同 fnb / mfg 现行做法）。
