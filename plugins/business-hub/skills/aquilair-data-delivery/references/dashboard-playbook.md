# 数据交付看板模板与分场景示例

> 由 `SKILL.md` 按需引入：需要拼装完整看板、定配色或参考分场景示例时读取。
> 出图通道按 SKILL.md 第五节宿主工具路由（本文件管看板结构与配色语义，与渲染工具无关）；兜底实现模板见 references/viz-templates.md。

## 一、豆包式看板标准骨架

```markdown
## 📊 {看板标题}

**口径**：来源 {实体名/服务名}｜时间 {数据时间戳或查询时间}｜范围 {仓群/工厂群/筛选条件}｜指标定义 {口径一句话}

> **结论**：{一句话结论，先说答案}

{图表：横向条形图}

| {维度列} | {指标1} | {指标2} | {判定} |
| --- | --- | --- | --- |
| 苏州区域仓（WH002） | … | … | P0 |
| … | … | … | … |

**洞察**：{差异点 + 归因 + 建议动作}
```

要点：
- **口径行不可省**：来源/时间/范围/指标定义四要素缺一不可，否则读者无法判断可信度。
- **结论在图之前**：图是证据，不是开场白。
- **明细表保留**：图表会压缩精度，明细表负责可溯源。超 20 行取最相关前 10 行并说明可展开。
- **洞察结语必须落到动作**：不止描述现象，要给出"下一步做什么"。

## 二、配色约定

| 用途 | 颜色 | 说明 |
| --- | --- | --- |
| 风险 P0 | 🔴 红 | 紧急 |
| 风险 P1 | 🟠 橙 | 高 |
| 风险 P2 | 🟡 黄 | 中 |
| 风险 P3 | 🔵 蓝 | 低 |
| 正常 / 达标 | 🟢 绿 | 无风险、满足率达标 |
| 关注 | ⚠️ | 需跟进但未达风险 |

- 涉及**金额/成本类指标且表达涨跌**时，遵循中国区习惯：**涨=红、跌=绿**。
  （本专家主要场景为库存与调拨，成本对比若用涨跌语义才适用此条。）
- 同一看板内色系不超过 4 种主色，避免用颜色区分超过 5 个分类。
- 宿主可视化工具锁定主题时（如 echarts 禁显式配色、visualize 主题 token），配色交由宿主主题，
  不强行内联色值——上表语义靠符号、条长差或描边样式冗余承载（见 SKILL.md 第五节跨通道数据纪律）。

## 三、分场景示例

### 场景 1：仓群风险总览（"谁多谁少" → 横向条形图）

- 图表：各仓风险 SKU 数 / 缺货量 **横向条形图**，按 P0→P3 降序。
- 明细：仓库（名称+编码）｜风险等级｜风险类型｜涉及 SKU 数｜状态。
- 洞察：点名 Top 2 风险仓 + 建议专项管控对象。

### 场景 2：SKU 周转对比（Top N → 横向条形图）

- 图表：周转天数 Top 10 **横向条形图**（标签为「SKU 中文名（编码）」）。
- 明细：SKU｜ABC 分类｜周转天数｜库存量｜判定。
- 洞察：区分"周转慢=超储"与"周转快但缺货"两类不同处置。

### 场景 3：调拨方案对比（多方案 → 分组柱状图+多图 / 需交互 → 网页看板）

- 图表：现有方案 vs 沙箱方案，按「总调拨成本 / 运输天数 / 满足率」**分组柱状图**。**多图/交互看板**：宿主工具出图（豆包 doubao-visualization / ZCode visualize），无工具时生成单文件 HTML 看板（套 `viz-templates.md` 模板 B/C），按宿主能力打开预览（ZCode 用 browser-use 新建标签页 / WorkBuddy `present_files`）。
- 明细：方案（编码）｜策略｜总成本｜运输天数｜满足率｜**环境来源**（生产/沙箱 xxx）。
- 洞察：必须**标注每个方案的环境来源**，禁止生产与沙箱数据混用对比而不标注。

### 场景 4：工厂可调出量对比（"谁多谁少" → 横向条形图+多图 / 需交互 → 网页看板）

- 图表：各工厂对目标物料的**可调出量横向条形图**。多图/交互看板：宿主工具出图（豆包 doubao-visualization / ZCode visualize），无工具时生成单文件 HTML 看板（套 `viz-templates.md` 模板 B/C），按宿主能力打开预览（ZCode 用 browser-use 新建标签页 / WorkBuddy `present_files`）。
- 明细：工厂（名称+编码）｜可调出量｜在途量｜到货时效。
- 洞察：给出推荐调出优先级与理由。

### 场景 5：沙箱推演评估（多图 / 需交互 → 网页看板）

- 图表 > 2 张或需切换维度 → 多图/交互看板：宿主工具出图（豆包 doubao-visualization / ZCode visualize），无工具时生成单文件 HTML 看板（套 `viz-templates.md` 模板 B/C），按宿主能力打开预览（ZCode 用 browser-use 新建标签页 / WorkBuddy `present_files`）。
- 至少包含：策略对比图、缺货满足率变化、成本分解。
- 明细：推演前后关键指标对照表，标注环境来源。
- 洞察：明确"是否建议在生产执行"及风险点。

### 场景 6：缺货响应（单图 + 明细）

- 图表：候选调出工厂的可调出量 **横向条形图**。
- 明细：工厂｜物料｜可调出量｜时效｜约束条件。
- 洞察：给出首选方案 + 备选方案 + 待确认事项。

## 四、常见错误

| 错误 | 正确做法 |
| --- | --- |
| 只给 Markdown 表格就说"如上表所示" | 表格之上必须有图 |
| 图上数值与表格不一致 | 两者必须同源，以工具返回为准 |
| 图表无口径说明 | 顶部口径行四要素补齐 |
| 用饼图展示 10 个仓库占比 | 改横向条形图 |
| 洞察只描述现象 | 补"建议动作" |
| 生产与沙箱数据混在一张图 | 分别取数、分组展示、标注环境来源 |
| 图上只写编码 | 改为「中文名称（编码）」 |
