# 数据类交付规范（Playbook）

> 本文件约束「数据类交付」的形态与标注纪律。凡交付物中**含有分析结论 + 数据**，即适用，
> 与结论由哪个技能产出无关（餐饮诊断 / 制造调拨 / 上市齐套 / 沙箱推演 / 跨源汇总一律适用）。
> **不强制配图，强制的是：结论可信、口径清楚、数值一致、来源可追。**

## 一、交付基线：结论在前，证据按需

1. **结论先行**：先给结论与判断，再给支撑证据与来源。任何形态（纯文字 / 表格 / 图表 / 文件）都遵守这一顺序。
2. **证据按问题给**：只给回答该问题所必需的证据，不为了"看起来完整"堆砌明细；证据要能定位到实体 / 记录 / 字段 / 规则。
3. **形态服从问题**——先判断"这个问题需要什么"，再决定是否出图、是否落文件。**判定参照问题锚定的本体子图：跨对象 / 多实体联动的分析类问题（依赖链、供应传导、跨周跨仓矩阵、方案比较）图比文字更清楚；单对象 / 单边查看直接文字作答**：

| 问题类型                       | 默认形态                  |
| -------------------------- | --------------------- |
| 普通查数（某指标是多少、某状态如何）         | 直接文字作答，必要时附 3~5 行关键明细 |
| 口径 / 规则解释（怎么算、为什么、取值定义）    | 直接文字 + 公式或规则原文，不出图    |
| 依赖链 / 供应传导（谁卡了谁、缺料怎么传导到门店） | 链路图或分层示意更能说清时配图       |
| 跨周 × 跨仓 × 跨物料矩阵、多维对比       | 矩阵表或热力图更能说清时配图        |
| 方案比较 / 沙箱推演 / 多版本对照        | 对比图更能说清时配图            |
| 用户要求"报告""看板""可下载明细"        | 按用户指定格式落文件（见第六节）      |

4. **不强制落档**：一次简单问答不产 HTML 看板、不产文件。"因为规范要求"不是生成文件的理由。

## 二、需要配图时的形态选择

先判复杂度，再选形态；**拿不准时按复杂处理**。

- **简单**：涉及实体≤ 2、分类 ≤ 6、单/双指标、一次性对比、无需筛选——2~4 张独立图表，或一张静态看板。
- **复杂**：多指标多维度（跨仓/跨 SKU 缺口矩阵、多订单到货跟踪、方案多维对比）、需筛选/下钻、或任一维度分类 > 6——交互看板（静态首屏可读 + 筛选/下钻/联动）。

通用要求：图表是证据，不能替代结论与证据文字；结论段始终在最前。需要留档时优先**自包含单文件**（内联 CSS/脚本、无外部依赖），文件名含场景与数据口径日期。用户只要文字时照做，不加图、不加文件。

## 三、出图通道（脚本渲染优先）

**核心原则：图表代码不由模型手写。** 模型只产「图表规格 JSON」（图型 + 数据 + 口径 + 结论段），由本技能 `scripts/render_dashboard.py` 确定性渲染为自包含 HTML（零依赖、内联 SVG），再用宿主预览打开——手写多图看板需数千 token、耗时百秒级，脚本毫秒级渲染，数值直写图元，天然满足「同源不重算」。

**可用脚本**（本技能 `scripts/` 下）：`render_dashboard.py` 渲染入口；`chart_renderers.py` / `chart_renderers_ext.py` / `chart_renderers_adv.py` 渲染层（由入口导入，无需直接调用）。调用方式（规格结构见脚本文件头 docstring，可选 `--quiet` 只打印输出路径）：

```bash
python "<本技能目录>/scripts/render_dashboard.py" --spec <规格>.json --out deliverables/<场景>_<口径日期>.html
```

- **已支持 12 图型**：`bar` 柱 / `hbar` 条形（长名称、Top N）/ `line` 折线（趋势）/ `donut` 环形占比 / `stacked` 堆叠构成 / `heatmap` 矩阵热力（缺口矩阵）/ `progress` 进度对比（含目标线）/ `scatter` 散点（ABC 分类）/ `dual` 双轴组合 / `radar` 方案多维对比 / `gantt` 甘特排期 / `svg` 逃生舱；规格写法参照 `scripts/example-spec.json`；看板另含 KPI 卡组、明细表、结论段、口径行、洞察结语。
- **报错处置**：负值输入报错（退出码 2）——按提示把差额类数据拆「方向 + 绝对值」两列或放明细表后重跑，**不得改数值迁就渲染**（呼应数值同源纪律）；其他报错按报错信息修规格 JSON 后重跑，禁止静默改为手写出图。
- **手写边界（硬约束）**：仅 `type:"svg"` 逃生舱允许手写，且必须是图库图型未覆盖的**单图**；禁止整页手写看板，禁止绕开脚本重画图库已有的图型，禁止为「交互」临时手写 JS。
- **落档位置**：写入当前工作区 `deliverables/`（或用户指定目录）——**绝不写入技能目录**（技能目录是分发物，交付产物不得混入）。
- **通道探测序（脚本满足不了时）**：按序探测当前会话能力，首次命中即定通道；工具缺失不修环境、不现场安装，直接落下一层——① 技能列表含 `doubao-visualization`（豆包侧安装）→ 精确数值走其 `echarts` 代码块、结构图解/看板走其 `html type="renderer"` 块；② 技能列表含 `visualize`（ZCode 官方插件）→ HTML fragment 写宿主可视化目录 + `::visualize` 引用；③ 宿主原生展示组件（WorkBuddy `show_widget` / `present_files`）→ 内联单图走组件，多图/交互走 HTML 看板 + 文件预览。需筛选/下钻/联动时脚本先出静态首屏保底，真交互再转宿主工具。**脚本与三层均不可用**：零依赖 HTML / SVG 直呈（内联 CSS/脚本，无外部依赖），不修环境。留档例外：嵌入 docx/pptx、正式归档走 PNG；文档宿主走 Mermaid 代码块。
- **回传与引用（多成员协作时）**：成员交付时须回传**落档 HTML 路径 + 规格 JSON 路径**，不贴图表代码、不贴 HTML 全文；装配方（主理人）直接引用成员的图路径，**不重复出图**，仅「跨域合并总览图」才另出一张。

**跨通道数据纪律**（任何通道出图都必须满足；与工具自身规范冲突时以下列为准）：①**数值同源**——图上数值 = 工具返回值，禁止为构图修数（「禁止重判/禁自算」优先），坐标从合理基线开始、占比用整体=100% 的图，不得歪曲数据；②**名称规范**——仓库/工厂/物料/SKU 一律「中文名称（编码）」；③**来源标注**——图 / 看板必含口径（来源实体 + 环境 + 日期）；④**结论先行**——看板骨架与单图均按第二节，结论段在最前；⑤**配色**——宿主工具锁定主题时交由宿主主题，不强行内联色值；语义色约定 绿=正常/通过、红=告警/不通过、黄=待核查（业务域有专属语义色时以其为准）。

**Top N / 排名类交付两项硬要求**：①明细表须含分类维度与库存水位（如 ABC 分类、在库量），不得只列排名与指标；②洞察须区分**「超储条目」与「缺货条目」**两类处置——榜单中周转快但缺货的条目不应建议压库存，须单列补货处置并在图上做视觉强调（如红描边）。

## 四、数值一致性：所有形态同源

- **同一份已核实数据**贯穿文字、表格、图表、文件；图表数值与正文逐处同值，同一数据只算一次。
- 交付须注明口径四要素：**工作区 / 计划·版本·分支 / 检查日 / 单位**，并明确**数据完整性**（完整覆盖 或 部分覆盖 + 覆盖范围）。

## 五、标注纪律：计算结果、系统回写、未知值必须分清

1. **展示层计算**与**系统回写结果**分别标注，不混为一谈（如：齐套结果取系统值，汇总求和为展示层计算并注明公式）。
2. **未知不等于零**：缺失、未采集、待核查的项，标为"未知/待核查"，不得画成 0、不得归入"正常"、不得从分母中静默剔除。
3. **未来不等于已发生**：计划供应、预计到货、预测需求不得呈现为已到货 / 已实现；时间轴上须区分"已发生 / 计划中"。

## 六、表格、编号与文件交付

- 名称一律**「中文名称（编码）」**；订单号、需求编号、批次号等**保持系统原值**，回显前与工具返回逐字核对。
- **Top N 必须注明排序依据与筛选条件**；截取明细不得表述为全量结论（如"前 10 条"不能说成"共 10 条"）；明细超 20 行时展示最相关前 10 行，说明可展开范围；建议与事实分开陈述。
- **文件交付按用户所需格式**（Markdown / CSV / Excel / HTML / docx / PPT），用户没指定时按场景给最小可用格式；HTML 需要带走（转发、归档、离线打开）时尽量**自包含**（内联样式与数据，不依赖外部 CDN 与本地路径）；文件只是承载物，文件内同样遵守第四、五节；不在用户未要求时生成文件，生成后说明路径与内容范围。

## 七、工具选择：用宿主已有的，不假设、不安装

- **只使用当前宿主已支持的可视化 / 文档工具**：先探测本会话可见能力，再选通道（探测序见第三节）；**不假定特定宿主指令存在**（不硬编码某个宿主的专用语法）；**不为出图安装新工具、不修改环境**；工具缺失时降级即可，并在交付中说明形态降级原因。

## 八、交付自检（输出前必做）

1. 结论是否在最前？证据是否足以支撑结论并且可溯源？
2. 形态是否匹配问题类型（没有为凑图/凑文件而加东西）？配图判据是否回到「图比文字更清楚」（参照问题锚定的子图）？
3. 各形态数值是否同源同值？口径四要素与数据完整性是否写明？
4. 计算结果 / 系统回写 / 未知项 / 未来计划是否分别标注？
5. 汇总是否同物料同单位？Top N 是否注明排序与筛选？
6. 名称是否「中文名（编码）」？编号是否原值？

## 九、边界说明

- 纯知识型问答（概念解释、口径说明、规则释义）与协议式确认卡**默认直接文字/卡片呈现**，配图仅在能显著辅助理解时使用（如三态流程图、规则判定树）。
- **用户指令优先于本规范**：用户明确只要文字时，不再附加图或文件；用户指定形态时按用户要求执行。
- 本规范**不覆盖**各业务技能的业务铁律（禁止重判、写前确认、名称展示等），两者叠加执行；域内图型对照、落档命名等细化见各技能自带 references。

## 按需加载

- **常规出图（默认路径）**：只需读本文件第三节 + `scripts/render_dashboard.py` 文件头 docstring（规格结构），**不要**通读脚本源码。
- **宿主可视化工具已装且脚本满足不了（第三节探测序第 1/2 层命中）**：加载对应技能（`doubao-visualization` / `visualize`），按其自身规范出图；本技能仍做交付自检（第八节）与数据纪律核对（第三节）。
- **域内场景图型与宿主模式细节**：读对应业务技能自带的交付细化文档。
