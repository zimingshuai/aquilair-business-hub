# 数据交付可视化规范（Playbook）

> 本文件是「数据类交付」的强制规范。凡交付物中**含有分析结论 + 数据**，即命中本规范，
> 与结论由哪个技能产出无关（餐饮诊断 / 制造调拨 / 上市齐套 / 沙箱推演 / 跨源汇总一律适用）。

## 一、铁律：默认强制配图

**任何数据分析类交付，默认必须配可视化图表和看板。只回纯 Markdown 文本表格视为违规。**

- 表格不是图。Markdown 表格只是明细承载物，不能充当可视化。
- 配图是默认动作不是可选项；用户明确说「不要图 / 只要文字」时才豁免，且此时仍须保留结论段。
- **两档交付均须落档**：无论简单还是复杂，都要产出自包含 HTML 看板文件存档（见第三节）。

## 二、交付自检（输出前必做）

1. 交付含分析结论 → 交付物里必须有图表 / 看板（宿主可视化输出、HTML 看板均算，纯 Markdown 表格不算）。
2. 图上数值 = 工具返回值，与正文 / 明细表**处处同值**（同一数据只算一次）。
3. 图 / 看板标注来源（来源实体 + 环境 + 日期）。
4. 结论先行，落档文件已产出。

## 三、复杂度两档（先判档，再选形态）

所有业务技能统一适用（2026-10-29 自 launch 域实测上收，口径以其为准）：

- **简单数据**：分类 ≤ 6、单指标或双指标、一次性对比、无需筛选/下钻——如六类状态总览、子项通过率、简单对比。
- **复杂数据**：多指标多维度（跨仓/跨 SKU 缺口矩阵、多订单到货跟踪、方案多维度对比）、需筛选/下钻/联动探查、或任一维度分类超过 6 个。
- **判定先于出图；拿不准时按复杂处理**（复杂覆盖简单能力，宁可多做一次落档）。

| 档位 | 形态 | 要求 |
| --- | --- | --- |
| 简单 | **多图图表组 + 静态看板落档** | 2~4 张独立图表，每图数值与正文一致、不硬编码颜色；另产自包含单文件 HTML 静态看板（内联 CSS/脚本、无外部依赖、静态首屏完整可读）→ `deliverables/` |
| 复杂 | **交互看板 + 落档 + 数值图** | ① 对话内交互看板（静态首屏可读 + 筛选/下钻/联动）② 自包含 HTML 落档 `deliverables/`（文件名含场景与数据口径日期）③ 另配图表承载精确数值 |

- 看板与落档 HTML 用**同一份数据、同一口径**；落档页脚注明数据来源与生成日。
- 无论哪档：交付时先给 3~5 行**结论先行摘要**，看板不能替代结论。
- 默认看板骨架（自上而下）：**结论段 → 顶部口径（来源/时间/范围/指标定义）→ 图 → 明细表 → 洞察结语**——图是证据不是开场白，禁止排在结论之前。

## 四、出图通道（宿主可视化工具优先）

**路由探测序**（按序探测当前会话可用能力，首次命中即定通道；工具缺失不修环境、不现场安装，直接落下一层）：

| 层 | 探测信号（当前会话可见） | 出图通道 |
| --- | --- | --- |
| 1 | 技能列表含 `doubao-visualization`（豆包侧安装） | 图表交该技能：精确数值（趋势/占比/排行/对比）→ 其 `echarts` 代码块；结构图解 / 看板 → 其 `html type="renderer"` 块 |
| 2 | 技能列表含 `visualize`（ZCode 官方插件） | 图表交该技能：HTML fragment 写宿主可视化目录 + `::visualize` 引用。其「用户要表格就直接给表格」条款与本案冲突时**铁律优先**（业务数据交付必须配图） |
| 3 | 宿主原生展示组件（WorkBuddy `show_widget` / `present_files`） | 内联单图走组件；多图 / 交互走 HTML 看板 + 文件预览 |

- **三层均未命中**（工具全未装）：零依赖 HTML / SVG 直呈（内联 CSS/脚本，无外部依赖），不修环境。
- **留档例外**：嵌入 docx/pptx、正式归档走 PNG；文档宿主（GitLab / GitHub）走 Mermaid 代码块——留档与对话内直呈无关，不因路由改变。

**跨通道数据纪律**（任何通道出图都必须满足；与工具自身规范冲突时以下列为准）：

1. **数值同源**——图上数值 = 工具返回值，禁止为构图修数（「禁止重判」优先）；坐标从合理基线开始、占比用整体=100% 的图，不得歪曲数据。
2. **名称规范**——仓库/工厂/物料/SKU 一律「中文名称（编码）」。
3. **来源标注**——图 / 看板必含口径（来源实体 + 环境 + 日期）。
4. **结论先行**——看板骨架与单图均按第三节，结论段在最前。
5. **配色**——宿主工具锁定主题时（echarts 禁显式配色 / visualize 主题 token）交由宿主主题，不强行内联色值；语义色约定 绿=正常/通过、红=告警/不通过、黄=待核查（业务域有专属语义色时以其为准）。

**Top N / 排名类交付两项硬要求**：①明细表须含分类维度与库存水位（如 ABC 分类、在库量），不得只列排名与指标；②洞察须区分**「超储条目」与「缺货条目」两类处置**——榜单中周转快但缺货的条目不应建议压库存，须单列补货处置并在图上做视觉强调（如红描边）。

## 五、边界说明（豁免场景）

以下场景**不适用**强制配图，但**同一份交付里若出现分析结论，仍须配图**：

- 纯文字问答（概念解释、口径说明、规则释义）
- 协议式确认卡（Action 确认卡、参数核对卡）
- 用户明确点名要 CSV / Excel 等可下载文件

## 六、与既有技能的关系

- 本规范**不覆盖**各业务技能的业务铁律（禁止重判、写前确认、名称展示等），两者叠加执行。
- 域内交付细化（场景图型对照、落档命名、模拟时间轴口径、宿主模式细节）见各技能自己的 references。

## 按需加载

- **宿主可视化工具已装（第四节第 1/2 层命中）**：加载对应技能（`doubao-visualization` / `visualize`），按其自身规范出图；本技能只做交付自检（第二节）与数据纪律核对（第四节）。
- **域内场景图型与宿主模式细节**：读对应业务技能自带的 delivery 细化文档（如 launch 域的齐套交付规范）。
