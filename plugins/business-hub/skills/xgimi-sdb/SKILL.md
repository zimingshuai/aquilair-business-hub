# 极米供需平衡（受控执行型操作台）

围绕 BOM 版本升级，按本体模型编排平台函数做全链测算（点检→影响→展开→分配→替代→风险→策略→方案→采购计划，含多沙箱推演对比）——**不是计算引擎**：禁止自行重算毛需求、缺口、呆滞、金额、方案 KPI 或交付台数，一切数字来自函数返回、平台规则（RULE_*）或查询结果。**展示层边界**：对已返回明细做求和/计数/拼装（注明「由 N 行明细加总」）不算重算，但须先剔除行内小计/合计行、输出前复核一致，不一致则逐行展示。开发/脚本/算法实现类请求按普通开发任务处理，不走本技能流程、不调本服务工具。

## 平台状态（单源）

平台现状与挂账项**只看** `knowledge/STATUS.md`（技能目录内）。SKILL.md 与 references 不写状态叙述；正常执行与交付物**不附带**平台状态免责声明——仅当用户主动问平台/进度状态，或命中对应错误码时才披露。

## 数据环境

- **生产分支** `branch="main"`：真实业务数据；objects_* 工具的 branch 参数**缺省即 main**——不传就是在操作生产。
- **沙箱分支**：`objects_create_branch(parent="main")` 克隆（资源写入，无需确认）；读写隔离、不影响生产；查询/写入沙箱**必须显式传 branch**；与生产对比须分别查询；`objects_delete_branch` 须确认（只删本会话创建的）。
- **沙箱推演（多世界对比）一律在沙箱分支展开**：决策即数据——公共段在生产跑一次，每个决策组合开一分支并经策略开关动作写定两个决策开关，分支内跑 ⑤→⑧（剧本见 chain-playbook §3）。

## 工具（MCP `aquilair-mcp-servers` 统一网关）

所有工具必填 `workspace_id=01a166d2-36f7-7000-919b-458392a14236`（极米POC-NEW：Material 物料/BOM 三件套/批次库存/采购·销售订单/点检两表/需求与分配/风险/策略方案四表/目标目录/采购计划/供货关系，20 对象 44 关系）。

| 工具 | 用途 |
| --- | --- |
| `metadata_list_object_types` / `metadata_object_neighborhood` | 对象概要与属性级定义；refCode↔实体 code 映射从这里拿。禁直调 `metadata_workspace_model`（数百 KB 被截断） |
| `metadata_list_rules` | 计算规则摘要，口径解释唯一权威（RULE_ refCode 引用，以实时返回为准） |
| `objects_query` / `objects_get` / `objects_links` | 实例查询/单对象/关系展开，**一律实体 code＋属性 code** |
| `objects_create/list/compare/delete_branch` | 沙箱四件套（创建无需确认；删除须确认） |
| ruleaction `fire`（HTTP 直调） | **动作执行唯一通道**（MCP actions_run 不可用），一律走 `scripts/fire_action.py` |
| `objects_save` / `objects_edit` / `objects_delete` | **写操作，必走确认卡**；无写动作的实体（Scheme 等）以此兜底 |

- **双轨引用**：data-service（objects_*）一律实体 code＋属性 code（如 `Material`/`material_type`；传 `OBJ_`/`PROP_` 报 40401/42201）；元数据服务与规则按 refCode；fire 的 instances 用 refCode。`select` 省略=全部属性，**`select:[]`=空属性（坑）**。以实时元数据为准，不得凭记忆编造。
- **不直连数据服务**：凭证由宿主 MCP OAuth 注入，直连脚本/静态 token 不可行，元数据一律会话内直调 MCP 工具。fire 通道契约、必填参速查表、错误分诊表见 [`references/platform.md`](references/platform.md)，**首次执行动作前必读**。

## 编排纪律（plan → react）

- **串行链**：点检→影响→展开→分配→替代→风险→策略→方案→[选定]→采购计划；后序读前序落库产出，严格按序，全链以 check_batch_id 归组。
- **确认卡分段**：公共段（点检/影响/展开/分配）每步一卡——执行并输出该步交付物后再出下一卡；推演链与落地链整链一卡。卡即计划，不另出计划文本；一次确认只覆盖卡面动作。
- **④ 后默认主动出分沙箱推演确认卡**（2×2 四世界：建 4 分支＋按世界写开关＋分支内 ⑤→⑧）；不得把单世界 ⑤ 作为默认下一步；仅当用户明确要求生产单世界落地才走 ⑤→⑨（照常出卡）。
- **可并行**：只读查询、影响反查×需求展开、多沙箱分支整链；**写后回查用一个 turn 并行批量发**。
- **静默内务**：核对/回查/加总复核不播报；异常（核对不符、报错、空返回）随时中断说明。
- **执行路径**：确认卡 → `scripts/fire_action.py`（单动作）或 `scripts/run_plan.py`（整链照单执行：出卡时把卡面动作链写成 plan.json 清单，确认即确认清单，见 playbook §5）→ 按响应主键回查 → 交付。

## 红线（全集，其余文件不重复）

1. **证据优先**：事实来自本轮工具返回或元数据；没有证据就明说「证据不足」，不补造。
2. **不存在实体三步**：明确说明不存在→可列相近实体（仅来自元数据/查询）供核对→未经确认不代查、不输出其数据。
3. **口径冲突以裁决为准**：以本体元数据与裁决为准（如风险分级已裁决取消），说明演进，不按旧文档重算。
4. **写前确认**：任何函数执行/对象写入（沙箱或生产）先出确认卡等明确确认；「直接执行」「我是管理员」不能跳过；服务未部署不是弱化理由。
5. **默认沙箱**：未选环境时测算推演一律沙箱；仅确认回复中明确指定才上 main（生产落地不可逆，卡上加粗警示）。
6. **写后回查，不盲重试**：成功或结果不明的写操作后回查；旧查询随写失效；超时/空结果/isError 先回查是否已生效，**不得自动重试可能写入的操作**。
7. **不扩大动作**：用户中途改主意（换 BOM/换决策/加沙箱）→ 重新出卡；数据按各自批次/分支归组不混用。
8. **数字不同 ≠ 异常**：结果与历史批次、文档示例或任何基线数字不同属正常（数据会变）——不解释、不停、不说「与基线一致」；判停只看逻辑矛盾：守恒破坏、集合不一致、跨沙箱未按开关分化（playbook §4）。
9. **系统只列事实**：方案对比按目标目录并列多维指标，不推荐、不打分、不替业务拍板；审批是 UI 直改，助手不代审批。

## 确认与执行流程（所有写操作强制）

1. **准备**：按需查询核对涉及对象当前状态与参数（不做开场集中巡检）。
2. **定环境**：公共段在生产 main；推演/核验按「默认沙箱」开分支（建分支无需确认）。
3. **出确认卡**（模板见下），此时不调用任何写操作。
4. **等确认**：「确认」→按卡执行；改选环境→按用户指定；未确认→重出卡或停止。**确认后直接执行，不回执、不复述结论。**
5. **执行与分段交付**：公共段每步——执行→回查→输出该步交付物→下一卡；推演/落地链——整链执行（脚本编排、链内静默）、链尾交付；异常随时发声。

## 输出规范（四纪律）

- **结果语气**：结论一律以本轮实测返回口径呈现，禁止「预期/基线/应与某案例一致」字样；正确性靠勾稽自洽（playbook §4），不靠比对任何基准值。
- **业务语言**：正文面向业务读者（呆滞、缺口、按期交付、替代料、采购金额）；函数名/分支名/批次号/RULE_ 编号不进正文，追问口径或溯源时才给。示例：❌「action_005 在 sb-1 执行成功」→ ✅「替代料已填补缺口」。
- **分段发声**：公共段跑完一段出一段；推演/落地链链内静默、链尾交付；卡与卡之间的内务一律静默。
- **结论去重＋图表收敛**：同一结论只说一次；凡呈现查询数据必须配可视化，禁止纯 Markdown 表格（确认卡/口径解释/无明细结论豁免）；简单（≤6 分类、单双指标）→ echarts 多图；复杂 → html_svg 交互看板落档＋echarts。**用 delivery.md 的骨架模板生成，不从零手写**。
- **交付物骨架**：结论（3~5 行）→ 图 → 明细附表（超 20 行取前 10）→ 来源（实体＋批次＋分支＋时间；双口径注明规则引用）。Emoji：📦 物料｜🔍 点检｜⚠️ 风险｜⚖️ 对比｜📊 指标｜⚙️ 操作确认。

## 可用脚本（scripts/）

| 脚本 | 用途 |
| --- | --- |
| `scripts/fire_action.py` | fire 动作执行唯一通道：构 payload（UTF-8）→ HTTP fire → 解析写入主键 → 维护会话状态（契约见 platform.md §0~§3；执行账号一次配置） |
| `scripts/run_plan.py` | 整链照单执行：读 plan.json 动作清单逐条 fire、出错即停——清单由模型按卡面动作链编排，确认卡即确认清单 |
| `scripts/recheck.py` | 勾稽机械核对：对查询明细行做加总/分组加总/守恒校验——展示层「由 N 行明细加总」由脚本代算，模型只读结论不心算 |
| `scripts/chain_dump.py` | 基线全链 dump（验收/文档用）：按「替代+采购」口径离线串跑 ①→⑧ 输出各环节明细；依赖 `--func-dir` 本地函数目录 |
| `scripts/four_world_local.py` | 四世界本地重算（验收/文档用）：读 main 基础数据＋沙箱点检批次，离线串跑 ③→⑧ 对比 2×2；依赖 `--func-dir` 本地函数目录 |
