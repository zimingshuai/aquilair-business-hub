# 全流程场景剧本（scenario-demo）

> 端到端验收动线：公共段四卡四交付物，推演与落地各一卡一交付物，每卡等用户确认。本剧本不含任何预期数字；输出遵守 SKILL.md 输出规范（业务语言、结果语气、过程静默、图表收敛）。

## 前置（按需，静默）

用户开场即要全流程时：核对两版 BOMHeader（同 output_code、正式计划版）后直接进第一站；不做开场集中巡检。

## 第一站：公共段（四卡四交付物）

1. **用户**：「当前产品要从 BOM V1 升 V2 了，帮我推演一下升级后的供需情况。」（产品与 BOM 版本不预置——先实时查 BOMHeader 发现，多对并存时向用户确认）
   **助手**：按环节分段出卡，每段「卡 → 确认 → 执行 → 该段交付物」：
   - **卡① 点检** → **差异清单**：六类差异用业务话讲清（以实跑差异行为准，逐类讲业务含义），配差异类型图；
   - **卡② 影响反查**（只读）→ **影响概览**：变化物料反查受影响成品与在手订单、影响等级＋繁杂度（一进一出：进入/退出/净额，退出含 BOM 删除与物料失效时间 expire_time ≤ V2 生效日的并集去重，注明「展示层口径」，见 caliber §10）；
   - **卡③ 需求展开** → **需求概览**：每物料毛需求（根需求=订单未交付合计）；
   - **卡④ 供需分配** → **缺口概览**：每物料可用供给与分配后缺口，配图；注明这是四个世界共同底账。分配订单归属（sales_order）继承自需求行、先保早交期单——函数升级后可按订单下钻（caliber §11）；
2. 每卡写明：环境（main）、动作、关键参数（含批次传递）、影响实体、不可逆性；确认后才执行。

## 第二站：分世界推演（一卡 → 静默 → 「四种打法对比」）

3. 公共段完成后**助手主动出确认卡**（不等用户发问）：开 4 沙箱＋按世界写开关＋每分支 ⑤→⑧（出卡时生成 plan.json 清单，确认后 run_plan.py 照单整链执行）。
4. **交付物「四种打法对比」**：四沙箱对比看板（目标目录 8 维并列：按期交付、延迟交付、剩余缺口、剩余呆滞、采购数量/金额、附带成本、预计周期，数字全部来自本轮实跑）＋结论式讲解（句式固定、数字现场填）＋风险/替代明细收进看板下钻。**系统列事实，人拍板**。

## 第三站：选定落地（一卡 → 「怎么落地」）

5. **用户**：「选定世界 1，生成采购计划。」→ 确认卡（选定置状态＋⑨；默认沙箱核验；正式落地 main 单独确认＋加粗不可逆警示）。
6. **交付物「怎么落地」**：采购计划汇总（建议量、供应商、待审批）＋计划看板＋审批边界说明（待审批→已下达是 UI 直改，助手不代审批）。

## 常见追问应答（追问才答）

- 「风险为什么不分级？」→ OQ-003 裁决（caliber §3）。
- 「为什么没有取消采购/延期到货的测算行？」→ 策略库基线只有两策略，加行即参与下轮（caliber §4）。
- 「沙箱怎么做的？」→ 平台分支机制：每分支完整数据副本、隔离运行；四世界差别只在建箱时写入的两个策略开关，函数与模型不含沙箱概念。
