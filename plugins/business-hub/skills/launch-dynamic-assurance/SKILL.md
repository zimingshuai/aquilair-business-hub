# 新品上市前问答与供应保障

围绕明确的上市根计划，回答「现状是什么、差在哪里、影响哪些需求、依据是什么、建议先处理什么」。读取业务结果、核查关联证据，区分系统事实、展示计算和业务建议。**读写分离**：本技能只读与解释；创建、修改、确认、下发、重算等动作执行一律转 `launch-assurance-actions`（其确认卡与快照纪律见该技能）。

## 接入与证据

- 工作区固定为 `01a19ac6-4c5f-7000-8c2d-4cfe7158ca8f`；每次工具调用显式传入，禁止按相似项目名称替代（网关下存在相近名项目，以 `list_workspaces` 实时返回为准）。
- 首次探测可用工具及其参数，再用轻量元数据发现对象，按需取属性、关系、规则和动作定义。对象、字段、关联与动作清单以实时元数据返回为唯一权威，不依赖任何历史快照或字段清单副本。
- **MCP 不可用时如实报告不可达与已尝试的环节，不用缓存数据或文档演示值冒充查询结果**；只有文档或模型定义时只回答口径和结构，不宣称查到了当前业务状态。
- 元数据证明对象/字段/动作「已定义」，不证明实例已生成、规则已生效或外部通知已发送。
- 文档、字段说明、表达式不一致时分别说明业务要求与实际配置，不能用文档描述覆盖表达式，也不能把实际配置解释成已满足全部业务要求。

## 探查循环（以 MCP 实时查询为唯一事实源）

1. **锁范围**：解析计划编码、计划版本、预测版本、分支及检查日期；复用同会话已明确上下文。用户只问列表时直接列计划；需要单计划诊断而有多个候选时，再请其选定。
2. **选路径**：按 [问法意图路由](references/storyline-playbook.md) 归类问法并选择探查环节；复合问题合并证据，不机械遍历全部实体。
3. **子图锚定**：依据元数据锚定问题涉及的对象类型与关系边（object_types 概览 + neighborhood / 关联冗余字段看关系存在性与基数），按子图规模规划查询深度与交付形态——单对象直查该类型、单边关系沿一条关系边取邻居、跨对象子图（2+ 跳 / 多实体联动）才展开多实体链路配完整诊断。**子图规模判定依据是元数据返回的关系与基数，禁止按问句动词枚举套深度**（问句措辞只用于理解意图）；探查范围以问题锚定对象的关系邻居为界。
4. **取实例**：按计划归属过滤，按需分页、选列、追溯；查询总数与分页完整性须核对，不能用第一页代表全量统计。互不依赖的多个查询放进同一条消息并发发出，仅续传或依赖前序结果时串行。
5. **核证据**：核对单位、日期、分配有效性和源记录；数量足够、按时足够、数据足够分别判断。缺口/状态优先引用系统存储结果；可能失效的结果明确标注。
6. **收口**：证据足以回答即停，不追求穷尽数据；覆盖不全时说明缺什么，不用默认值补齐。报错按码自纠（42200→查 DSL 结构；42201→核对属性实名；40401→确认类型可查性——entity_ 未命名实体通道不稳：实时尝试，失败按错误码如实报告，不编造），方言细节见 [服务端行为实测](references/facts.md)。

**时间基准**：涉及超期/剩余天数先查 `System` 实体（system_date=演示检查日，可能不等于真实日期），以检查日计算并注明来源；用户指定分析日期 > System.system_date > 真实查询时间，两种时间轴冲突时并列说明。

## 计算与不确定性

系统正式预测、齐套/分配、采购方案、风险记录优先引用规则/函数回写结果，**禁止自行重算**业务判定；不通过客户端重新跑业务引擎或直接改结果字段。允许为回答做筛选、同粒度同单位汇总、日期差、差额和占比，必须注明输入、口径和「展示计算」，不回写。

- **口径三分离**：原始经营目标 `target_first_month_sales_qty`（人工设定）/ 预测基准 `forecast_first_month_sales_qty`（参考品系数推导）/ 调整后最终目标 `final_target_sales_qty`（文本型，参与计算前校验格式，空值不转 0）——三值不同源不得混用；【待处理】规则引用时必须注明。
- 先确认 `MaterialKitting.kit_qty` 是增量还是累计，再汇总；不把齐套明细与分配明细相加，不对不同物料或不同单位求数量总和。公式分母为零、缺换算系数或日期格式不明时停止该项计算。
- 区分：业务未完成、数据缺失、接口读取异常、规则/动作配置限制。空值不是零，空集合不是通过，查询报错不是业务对象不存在。供应源变化后无重算凭据时，结果新鲜度标记待核查。

## 输出

默认用简短结论、必要明细和来源；建议与事实分开。来源至少包含工作区/计划/分支、检查日、对象编码/记录编号/字段。规则解释额外给规则名称与本轮核实的标识。

需要时展示表格：`周周期｜物料需求号｜物料/仓库｜需求日期与数量/单位｜有效供应与可用日｜系统缺口｜异常/待核查｜来源`。明细很多可给摘要与 Top N，但说明筛选和未展示范围，统计仍须完整。

图表与文件按实际阅读/交付需要选择，参照同包 `aquilair-data-delivery`：**交付随子图伸缩**——单对象或单边关系查看纯文本表格交付合法；跨对象子图（多实体联动、多维对比、趋势/分布分析）等分析类交付配图表看板（两档形态不变）。用户明确要求的交付格式优先。名称一律「中文名（编码）」；单据号回显前与工具返回原值逐字核对。

## 写操作（一律转动作技能）

收到创建/修改/确认/下发/重算类请求时不自行调用写工具（objects_save/edit/delete、actions_run），转 `launch-assurance-actions` 按其确认卡纪律执行；本技能层面不因「顺手」降级为直接改数据。

## 可用脚本

- [`scripts/save_meta.py`](scripts/save_meta.py)（纯存档，零网络零凭证）：首次或缓存缺失/过期时——调 metadata 四清单工具 → 把四段返回 JSON 按 `{"object_types":...,"rules":...,"actions":...,"algorithms":...}`（各键值=返回 content[0].text 原样，算法空传 null）包装存档至 `.meta-cache/`（命令带 `--workspace <id>` 记入归属）→ 后续会话直接读缓存省往返；`_cache-info.json` 的 fetched_at 超 7 天重拉（`.meta-cache/` 运行时生成不入库）。缓存与实时元数据冲突以实时为准。
