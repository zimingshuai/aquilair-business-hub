# 业务语义

> 出处：上市前业务场景文档 V8（revision 248）+ 同事包 aquilair-launch-poc-v2 重写版（2026-11-10 V8 大吸收）；决策枚举含 hub 2026-11-09 实测校注。

## 主流程与分支

创建上市计划 → 贯穿全过程的事项跟踪 → 参考品目标测算与业务调整 → 首月拆分周预测 → BOM 物料需求 → 获取最新供应情况 → 供需匹配/物料齐套 → 有新增缺口才生成采购计划 → 确认和分周下发 → 按需求追溯供应 → 风险识别处置。事项管理不是后续所有环节必须串行等待的总关卡。链路环节与上下文承接见 mrp-playbook.md「业务流程链路」。

全部按期齐套且无新增缺口时**不新增采购计划**。剩余缺口应扣除有效库存、在途和保留的未来采购供应，不能用毛需求直接采购。到货晚于需求日期，即使总数量足够，也不能判为按时全部齐套。

## 目标与预测

目标基准 = 参考品首月均店实销 × 季节系数 × 价格系数 × 门店系数 × 营销系数 × 新品首发门店数。用于解释依据，实际数值引用当前系统结果；待处理系数规则不能包装成已验证的测算。

系数口径（引用时核对规则实时状态）：

- 价格系数 =（新品定价 ÷ 参考品均价）^ 价格弹性系数；营销费用系数 = 1 + 0.4 × ln(新品营销预算 ÷ 参考品实际营销费用)。
- 季节系数 = 参考品过去 1–3 年各月总销量 ÷ 全年月均销量再平滑；全年均值为 0 或数据不足时不可计算。
- 上市实际均店销量 = 首月实销 ÷ 目标门店数量。

三个目标量三分离，不得混用：原始经营目标 `target_first_month_sales_qty`（人工设定）、预测基准 `forecast_first_month_sales_qty`（参考品系数推导）、调整后最终目标 `final_target_sales_qty`（文本型，参与数值计算前校验格式，空值不转 0）。

周占比 = 参考品对应周实销 ÷ 四周实销合计；周预测 = 最终目标 × 周占比。参考历史数据不足或分母为零时不强行均分四周。按仓分析需要门店—供应仓关系，不能把饮品×门店×日的销量直接称为仓销量。

物料需求使用已确认正式 BOM，逐层展开，考虑产出、损耗与单位换算；该环节本身不扣库存。历史参考品销量可作测算依据，不扩展为上市后销售复盘。

## 物料齐套与净需求

- 净需求/物料缺口 `net_demand_qty` = 毛需求 − 总齐套量（系统存储，规则回写；引用注明"计算回写"，不自行重算）。
- 分配约束：需求与供应的物料/仓库/单位必须一致；分配不超需求剩余、不超来源扣除已有有效分配后的剩余。
- 数量齐够但到得晚：单独表达时间不满足，不混入数量缺口。
- 先确认 `MaterialKitting.kit_qty` 是增量还是累计再汇总；不把齐套明细与分配明细相加。
- 最晚下发采购日期 = 物料需求日期 − 最大采购提前期（MAX(关联供应商 lead_time_days)，不跨仓全库求最大值）。

## 采购状态

| 业务状态   | 后续重算      | 供应保障解释                              |
| ------ | --------- | ----------------------------------- |
| 未确认未下发 | 可被新一轮计划覆盖 | 不作保留的稳定供应承诺                         |
| 已确认未下发 | 保留，不应被覆盖  | 计作未来供应，仍需核查可用日期、数量和有效性              |
| 已下发    | 以生成订单履约跟踪 | 原计划与对应订单避免双计；标记下发不等于已验证订单已生成或供应商已收到 |

确认采购计划＝该计划被保留，不会被后续计划覆盖；下发采购计划＝下发给供应商，形成新的采购订单。已确认未下发的采购计划在后续物料齐套计算中作为未来供应参与匹配；未确认未下发的采购计划会被后续计划覆盖。详细口径见 mrp-playbook.md「确认与下发」。

标记组合非法或含义缺定义时列为待核查；不能自行把 `confirm_flag=1` 当作所有环境通用约定。优先首周下发是业务默认，不是每次问答自动执行命令。MOQ/倍数造成的超量须单列，不能全当作本需求分配。

## 日期与就绪

计划就绪日与上市日分列读取；缺失时报告缺失，不自动设为相等。周需求日期、采购订单要求交期、预计到货日、事项计划完成时间各有用途。按时保障回到具体需求日期判断；不能用订单交期替代需求日期。

已过预计到货日仍未交完，或预计到货日缺失，属于到货时间待确认。最晚发货日期 = 订单要求交期 − 运输提前期是业务口径；实际规则有待处理标记时说明。

门店上架、培训和营销准备通过实际档案与上市事项检查；档案发布不等于门店可售；仓库供给不证明到店完成。

## 逾期/延期与提醒口径

- 订单交货逾期：未取消、未关闭、undelivery_qty > 0 且逾期天数 > 0。
- `current_overdue_days` = MAX(0, 当前日期 − required_delivery_date)；`expected_delay_days` = MAX(0, estimated_arrival_date − required_delivery_date)。前者看当前日期、后者看预计到达，两种口径不混用。
- 发货提醒窗：`latest_delivery_date` = required_delivery_date − transport_lead_time；`delivery_warning_day` 再减配置的提前提醒天数（参数不固定为任意天数）。

## 上市风险

`LaunchRisk` 实体已存在（risk_id 主键；plan_id、risk_type、risk_description、risk_level、source_instance_id、risk_status、owner、handling_note）。风险口径：

- 优先查该计划的风险记录并核对来源事项/需求/订单（source_instance_id 可能跨类型重名，结合 risk_type 验证）。
- 查不到风险记录不证明无异常；查询识别出的异常不是已登记风险。
- 风险规则引用时注意描述与实际条件可能不一致（如某逾期风险规则文本说"已超过最晚采购日期或需求日期"，实际条件是净需求>0 且系统日期等于需求日期）——引用时分别列出文本要求与实际表达式。

## 编码字典

- 单据号前缀：NP=上市计划 / MD-=物料需求 / PO-=采购订单 / SQ-=采购方案。
- NP009（青提冰茶，dish_id=926001）及 T=2026-11-15、首月目标 300000 杯、300 家门店等是**演示设定值**，不作事实源，数值以实时查询为准。

## 模拟

每方案单独新建根计划，记录参数和方案标识，复用主流程计算，跨根计划比较。优先比较同口径需求、按时缺口、齐套日期、采购数量和交期风险；成本数据完整且同口径时才比较成本。根计划隔离、共享供应资源如何隔离、采纳与写回机制还需实现验证，不能直接覆盖正式计划或宣称技术分支自动完成隔离。相同物理供应在不同方案中的比较结果不可相加成真实总承诺。

## 能力边界

- 无"检查上市齐套 / 重排齐套时间 / 采购成本测算"类动作承载；被要求执行时如实说明，不虚构接口。
- 首轮采购方案生成链路无算法承载；PurchaseSolution 仅基础字段（无目标测算字段），成本测算结果无落点。
- 供需分配无 expected_supply_qty_ontime / expected_gap_qty 字段；按时保障由 supply_available_date 与需求日期现算对比，注明"展示口径"。
