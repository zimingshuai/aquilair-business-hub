# 【新品上市POC】新品上市前——业务背景与功能说明

> 文档定位：餐饮新品上市 POC 业务背景与功能范围说明。

## 一、业务背景

### 1.1 业务背景

餐饮新品上市涉及菜品、配方、物料、仓库与门店供应关系、供应商等多个环节。新品上市计划明确计划上市日、计划就绪日、首月经营目标和上市门店范围。上市前需要利用参考品历史销量形成新品需求预测的参考基准，并将经营目标拆分成多个周期的需求，计算物料需求与缺口量，下发采购订单；根据计划就绪日倒退六类齐套工作的最晚计划完成时间和当前状态，指导各负责人完成齐套工作。

在物料齐套环节，系统依据预测需求、BOM、库存及在途采购计算物料齐套和净需求，生成首批采购方案及采购计划，并进行成本测算对比。采购订单形成后，通过订单状态、未交货量、预计到货日期及已交付量等数据跟踪到仓保障情况。

### 1.2 业务目标

- **需求有依据**：可查看参考品及历史销量，按需使用 AI 推荐并比较参考品，计算新品首月需求预测基准值，形成首月分周需求。
- **齐套有时间**：在上市前计划开始时，倒推六类齐套单元最晚开始与结束时间，为子齐套项负责人安排工作提供时间边界。
- **齐套有状态**：依据子齐套项、齐套单元的状态判断规则，了解六类齐套是否完成，并判断上市前计划的通过状态。
- **采购有方案**：识别物料毛需求、齐套量与净需求，在存在采购缺口时生成首批采购方案、采购计划及成本对比。
- **到货可跟踪**：查看采购订单的预计到货、未交货量、交付进展及订单状态，辅助判断物料供应能否按期到仓。

### 1.3 计划时间范围与边界

- 以新品计划上市日**T**为基准，计划范围为**可配置**的参数，默认为**T-28 至 T+28**
- 本文件重点描述**上市前**的计划、齐套、首批采购和采购在途保障。
- 六类齐套为：**商品、配方、仓配齐套、门店与营销、物料齐套、供应齐套**
- 供应齐套所述的到货保障聚焦**供应商到仓库**，目前**不包含**仓库到门店的末端配送与门店要货分配。

## 三、功能模块详细说明

### **3.1 新品分型**

**业务说明**：以导入的新品上市计划为入口，识别新品与已有参考品关联情况，提供参考品的历史销量信息查询。用户可以沿用或指定参考品，也可以选择使用 AI 参考品推荐结果，查看不同候选参考品的信息，辅助确认参考品。

**功能内容**

1. **新品上市计划及参考品查看**：读取新品计划基本信息以及 ReferenceDishBinding 中的参考品绑定关系，查看参考品菜品信息、关联参考上市计划及历史销量数据。
2. **参考品历史销量查看**：通过 HistorySalesByDay 查看参考品历史日销量信息；通过参考品关联的历史上市计划，可查看首月实际销量、首月四周销量等信息。
3. **参考品 AI 推荐（可选）**：调用本体中“新品参考品推荐规则”，根据新品品类生成参考品推荐结果。
4. **参考品对比（可选）**：在已查询的候选参考品间展示其基础资料、历史销量或关联历史上市计划数据，供业务人员比较。当前本体没有定义独立的“参考品综合评分规则”，因此不设虚构的评分、排序权重或自动最终选中逻辑。

**核心实体**：NewDishLaunchPlan、Dish、DishCategory、ReferenceDishBinding、HistorySalesByDay。

**对应规则**：新品参考品推荐规则。

**功能输出**：参考品绑定/候选结果、历史销量明细及参考品对比所需的已知数据。

### **3.2 新品需求**

**业务说明**：在获得参考品及其历史信息后，计算新品首月需求预测基准值，作为经营目标的参考依据；基于新品上市计划中的首月经营目标，形成周粒度的预测需求，为后续物料齐套计算提供需求输入。

**功能内容**

1. **参考品上市首月实销计算**：利用参考品历史销量及关联参考上市计划，计算参考品首月实际销量及四周销量，并回写参考上市计划中的相应字段。
2. **预测相关系数计算**：按本体已有规则与衍生属性，使用参考品季节系数、价格系数、营销费用系数、门店系数等计算预测新品首月均店销量。
3. **新品需求预测基准值计算**：通过 ReferenceDishBinding.forecast_average_sales_qty 等已定义关系计算 NewDishLaunchPlan.forecast_first_month_sales_qty。该值是**需求预测基准值**，与计划中 target_first_month_sales_qty（首月经营目标）属于不同字段。
4. **首月预测需求拆分**：依据参考品首月四周实际销量计算周销量占比，再将 NewDishLaunchPlan.target_first_month_sales_qty 按占比拆分为 **4 条周粒度 ForecastSalesDemand**；本体规则规定需求交期为各周周初日期。

**核心实体**：NewDishLaunchPlan、ReferenceDishBinding、HistorySalesByDay、ForecastSalesDemand。

**对应规则**：参考品上市计划首月销量计算规则、参考品季节系数计算、参考品价格系数计算（衍生属性）、参考品营销系数计算（衍生属性）、新品需求预测基准值计算规则（衍生属性）、预测需求拆分规则。

**功能输出**：首月需求预测基准值、首月经营目标及四条周粒度预测需求。

### **3.3 六类齐套**

**业务说明**：在进行齐套工作前，先以计划就绪日为约束，依据六类齐套上下游依赖和准备周期，计算六类齐套单元最大计划齐套时间。业务人员据此倒排子齐套项的时间并安排负责人准备工作，后续依据齐套状态判断规则跟踪进展。

**六类齐套范围**

| 齐套单元 | 本体/业务需求中的工作范围 | 上游约束 |
|-|-|-|
| 商品齐套 | 商品基础信息、销售规格及上市范围等准备 | 无 |
| 配方齐套 | BOM 配方及冻结/发布准备 | 无 |
| 仓配齐套 | 门店与上游供应仓库覆盖关系确认 | 无 |
| 物料齐套 | 基于预测需求、BOM、库存及在途计算物料齐套时间与数量 | 商品、配方、仓配齐套、门店与营销齐套 |
| 供应齐套 | 供应商向仓库交付及到仓可用保障 | 物料齐套 |
| 门店与营销齐套 | 门店上架、设备及培训等已定义准备情况 | 商品齐套 |

**功能内容**

1. **齐套单元最大计划时间计算**：在上市计划就绪日，触发“齐套单元最大计划齐套时间计算规则”，从 planned_ready_date 倒推六类 ReadinessUnit 的 max_readiness_start_date 和 max_readiness_end_date，并回写计算结果。
2. **子齐套项时间倒排**：用户依据父级齐套单元最大允许时间、子齐套项准备周期和依赖关系，倒排 SubReadinessUnit 的最晚齐套时间，并安排 plan_readiness_start_date、plan_readiness_end_date，明确 operator_code 对应负责人。**当前本体给出了子齐套时间字段，但未单独完整定义子齐套自动倒排规则**，因此此功能描述为业务排期及已知时间结果的应用，不假定存在可直接调用的独立算法。
3. **子齐套项齐套状态判断**：每次时间轴滚动，触发“子齐套项齐套状态判断规则”，获得 SubReadinessUnit.readiness_status。
4. **齐套单元齐套状态判断**：以上述子齐套状态为输入，触发“齐套单元齐套状态判断规则”，汇总得到六类 ReadinessUnit.readiness_status。已有规则明确：**所有子齐套项均齐套，齐套单元才视为齐套**。
5. **对应齐套业务触发**：到达齐套计划开始时间时，按六类齐套的业务范围及前置依赖，触发已经定义并可执行的相应规则或动作。当前本体未将六类齐套各自的完整检查规则全部展开，不在本文补造具体校验算法。

**核心实体**：NewDishLaunchPlan、ReadinessUnit、SubReadinessUnit，以及上述六类齐套涉及的 Dish、BOM、SupplyNetwork、NewDishLaunchStore 等业务对象。

**对应规则**：齐套单元最大计划齐套时间计算规则、子齐套项齐套状态判断规则、齐套单元齐套状态判断规则。

**功能输出**：六类齐套单元最晚开始/结束时间、子齐套项准备排期、负责人及六类齐套当前状态。

### **3.4 首批采购**

**业务说明**：在具备有效需求、BOM、库存及采购在途数据后，触发物料齐套计算，识别首批采购所需物料和净需求缺口。依据首批采购策略生成采购方案及采购计划，对方案进行成本测算和比较，为采购人员提供决策依据。

**功能内容**

1. **物料齐套计算**：以 ForecastSalesDemand 为根需求，结合有效 BOM、BatchInventory、PurchaseOrder，根据需求与供应优先级执行物料齐套算法。
2. **物料需求与缺口量**：读取 MaterialDemand 中的 gross_demand_qty（毛需求）、total_kit_qty（总齐套量）、net_demand_qty（净需求）；结合 MaterialKitting 和 SupplyDemandAllocation 展示物料齐套和供需匹配情况。
3. **首批采购方案生成**：针对净需求大于零的物料，依据 InitialPurchaseStrategy（首批采购策略） 中首批比例、供应商、提前期、最小/最大订货量及订货倍数，触发首批采购规则，生成 InitialPurchaseSolution 与 PurchasePlan。
4. **采购方案成本测算与对比**：调用“采购方案成本测算规则”，结合 InitialPurchaseObjective、InitialPurchaseSolution、PurchasePlan 对采购方案成本进行测算。查看不同方案的采购计划明细、物料、供应商、采购量、要求交货日期及采购成本，比较成本与交付条件。按业务需求设计，优先保障上市日和首月需求，再考虑同等保障水平下的采购成本。
5. **生成采购订单：**用户选定采购方案并确认采购计划后，根据采购计划生成采购订单。

**核心实体**：ForecastSalesDemand、BOM、BatchInventory、PurchaseOrder、MaterialDemand、MaterialKitting、SupplyDemandAllocation、InitialPurchaseStrategy、InitialPurchaseObjective、InitialPurchaseSolution、PurchasePlan、Supplier。

**对应规则**：预测需求优先级计算规则、实时库存供应优先级计算规则、采购在途供应优先级计算规则、物料齐套计算规则、首批采购规则、采购方案成本测算规则。

**功能输出**：物料需求及缺口、首批采购方案、采购计划明细及采购成本测算对比结果。

### **3.5 新品上市前保障**

**业务说明**：从“六类齐套是否完成”和“采购订单预计能否按期到仓”两个方面查看新品上市前的准备与供应保障情况。

#### **3.5.1 六类齐套状态**

1. 查询六类 ReadinessUnit.readiness_status 及关联的 SubReadinessUnit.readiness_status，查看每个齐套单元是否已经齐套、哪些子项仍未齐套。
2. 时间轴滚动后，先更新子齐套状态，再汇总六类齐套状态，触发“新品上市前计划通过状态判断规则”。
3. 依据该规则结果查看 NewDishLaunchPlan.plan_status，说明上市前计划当前通过情况；本体没有完整定义状态枚举和详细判断分支，不自行补充通过/不通过的具体状态编码。

**核心实体**：NewDishLaunchPlan、ReadinessUnit、SubReadinessUnit。

**对应规则**：子齐套项齐套状态判断规则、齐套单元齐套状态判断规则、新品上市前计划通过状态判断规则。

#### **3.5.2 采购订单跟踪**

1. **采购订单信息查看**：通过 PurchaseOrder 查看订单号、物料、仓库、供应商、采购日期、要求交货日期及订单状态。
2. **预计到货跟踪**：查看 estimated_arrival_date（预计到达日期）与 required_delivery_date（要求交货日期），了解采购订单的预计到仓安排。
3. **在途与交付量查看**：查看 total_order_qty、delivered_qty、undelivery_qty、status、cancel_flag、close_flag，识别订单已交付和剩余未交付情况。
4. **供应保障关联**：订单在途信息作为物料齐套计算的供应来源之一，通过 SupplyDemandAllocation 中的 PURCHASE_IN_TRANSIT 供应类型，查看哪些物料需求获得在途采购供应分配。

**核心实体**：PurchaseOrder、Supplier、Warehouse、SupplyDemandAllocation、MaterialDemand。

**对应规则：**

**功能输出**：六类齐套状态、上市前计划通过状态、采购订单预计到货日期、未交货量、已交付量、订单状态及对应在途供应分配信息。
