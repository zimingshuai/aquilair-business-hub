# 新品上市前风险管控 POC｜演示故事线与规则实体映射

> 演示主线：查看上市计划 → 经营目标评估 → 六类齐套倒排 → 当前齐套诊断 → 物料缺口 → 首批采购建议 → 到货可行性 → 上市风险及放行判断。仅覆盖 T 之前，不展示采购订单执行跟踪与参考品推荐。

## **一、故事设定与数据边界**

- 案例：Excel `NewProductPlan新品上市计划` 中 `NP009`，新品 `青提冰茶`，菜品编码 `926001`。
- T = 2026-11-15；计划启动日 T-28 = 2026-10-18；首月经营目标 300,000 杯；目标首发门店 300 家。
- 演示的时间轴全部在 T 前；实际齐套记录、风险状态以 Excel 演示数据为准，不代表真实业务执行。
- \*\*已确认业务口径：计划就绪日 = 计划上市日。\*\*NP009 的 `plan_launch_date = 2026-11-15`，因此演示采用 `planned_ready_date = 2026-11-15`（T）。源 Excel 该字段为空，采用业务默认值而非声称源数据已填写；齐套单元各自的计划最晚完成日仍按其时间安排展示。
- Excel 中 `NewProductPlan` 对应本体 `NewDishLaunchPlan`；`NewProductLaunchStore` 对应 `NewDishLaunchStore`；`MaterialRequirement` 表头实际是物料齐套明细，对应本体 `MaterialKitting`。这些名称需要做数据映射。
- `LaunchRisk` 已在 Excel 中出现，但不在所提供本体文档的实体章节中；风险创建、分级、关闭的自动化规则尚需定义。本故事线标注为 **建议新增**。

## **二、八个场景的详细对话脚本、规则与实体**

### 场景 S01｜新品上市计划

**时间 / 角色**：T-28（10/18），新品上市项目负责人。

**主 Query**：`帮我查看一下目前的新品上市计划。`

**示范系统回答**：

> 已查询新品上市计划。演示选中 **NP009｜青提冰茶（菜品 926001）**：计划上市日为 **2026-11-15**；按业务口径计划就绪日同为 **2026-11-15**；首发目标 **300 家门店**；首月经营目标 **300,000 杯**。可进一步查看计划状态、门店清单及关联齐套任务。

**后台执行**：检索 `NewDishLaunchPlan` → 关联 `Dish`、`NewDishLaunchStore` → 展示计划列表/详情；应用“计划就绪日 = 计划上市日”的业务口径。**无需新增业务计算规则**。

**验收点**：计划列表可下钻；销量目标与需求预测基准不能混淆；就绪日为空时能够明确说明默认口径。

### 场景 S02｜首月经营目标基准值

**时间 / 角色**：T-27（10/19），项目负责人 / 经营负责人。

**主 Query**：`结合当前的上市计划，评估一下首月经营目标是否需要调整？`

**示范系统回答结构**：

> NP009 的**首月经营目标为 300,000 杯**。系统读取/计算首月需求预测基准 `forecast_first_month_sales_qty`，展示：预测基准 =【系统实际计算值】杯、差额 =【目标 − 预测基准】杯、偏差率 =【差额 / 预测基准】。若有参考基准且偏差显著，提示负责人复核目标；\*\*当前未明确业务调整阈值，不自动判定必须调成某个具体数值，也不擅自修改计划。\*\*若缺失预测所需绑定或历史数据，应直接说明无法完成可靠评估。

**后台执行**：读取 `NewDishLaunchPlan.target_first_month_sales_qty` → 获取 `forecast_first_month_sales_qty`；需要计算时使用**新品需求预测基准值计算规则**，依赖既有 `ReferenceDishBinding` 与 `HistorySalesByDay`（只用已绑定参考数据，**不触发参考品推荐**）→ 计算差额与偏差率 → 提示是否需人工确认目标。

**验收点**：能给出可追溯预测依据；明确区分“预测参考”和“经营目标”；避免凭空提供阈值或调整后的销量。

### 场景 S03｜六类齐套

**时间 / 角色**：T-27（10/19），项目负责人。

**主 Query**：`为确保新品按计划上市，六类齐套工作分别需要在什么时间前完成？`

**示范系统回答**：

| 齐套类别 | 计划最晚完成日 | 计划安排（源数据） |
| --- | --- | --- |
| 商品 Q0001 | **2026-10-22** | 10/18–10/22 |
| 配方 Q0002 | **2026-10-27** | 10/23–10/27 |
| 仓配 Q0005 | **2026-10-27** | 10/23–10/27 |
| 物料 Q0003 | **2026-11-01** | 10/28–11/01 |
| 供应 Q0004 | **2026-11-06** | 11/02–11/06 |
| 门店与营销 Q0006 | **2026-11-06** | 11/04–11/06 |

> 计划就绪日为 **11 月 15 日**。以上为齐套任务自身的最晚完成日，并非统一都在 11/15 完成。将依据依赖关系和准备周期，按照**齐套单元最大计划齐套时间计算规则**倒排/核验；由于不同需求文档对部分依赖的描述存在差异，POC 先按数据表已配置的排期展示。

**后台执行**：读取 `ReadinessUnit` 的最晚起止时间及准备周期 → 调用/核验倒排规则 → 展开 `SubReadinessUnit` 和负责人信息（若有） → 时间轴展示。

**验收点**：六类完整且时间与源数据一致；能解释关键前置依赖，不把 11/15 当作每类齐套截止日。

### 场景 S04｜物料齐套

**时间 / 角色**：T-15（10/31 缺料历史快照），供应链计划负责人。

**主 Query**：`目前物料齐套情况如何？是否存在物料缺口？`

**示范系统回答结构**：

> 正在基于首月四周预测需求、有效正式 BOM、仓库库存及可用在途供应计算物料齐套。按【物料 × 仓库 × 需求日】展示**毛需求、可分配供给、已齐套量、净需求/缺口**。在 10/31 历史快照中存在**必需物料数量不足**风险 `LR-NP009-03`，但该风险在当前风险记录中已关闭。具体缺口物料与数量必须以本次物料齐套计算结果为准，不能仅凭风险描述填造。

**后台执行**：读取 `ForecastSalesDemand` → 正式 `BOM` 展开 `MaterialDemand` → 结合 `BatchInventory` 与已有在途供应执行需求/库存/在途优先级规则 → **物料齐套计算规则** → 写入/展示 `MaterialKitting`、`SupplyDemandAllocation` 结果。

**验收点**：物料缺口明细可追溯；解释“历史缺料已关闭”和“当前物料齐套状态”不矛盾；不进入采购订单执行跟踪。

### 场景 S05｜物料采购

**时间 / 角色**：紧接 S05 的同一缺料快照，采购 / 供应链计划负责人。

**主 Query**：`针对当前缺料的物料，有哪些可行的采购方案？`

**示范系统回答结构**：

> 针对 S05 查出的净需求大于零的物料，按首批采购策略生成候选方案：**物料、供应商、建议采购量、采购单位、要求交货日、预计可用日、方案成本、约束说明**。比较方案时**先判断能否满足各物料需求日期，再比较采购成本**。若供应商、价格、提前期或起订/倍数策略不足，明确指出缺少哪些参数，不虚构可执行采购方案。

**后台执行**：承接 S05 的 `MaterialDemand` 净需求 → `InitialPurchaseStrategy`（首批比例、提前期、MOQ、订货倍数、供应商约束）→ **首批采购规则**生成 `InitialPurchaseSolution` 与 `PurchasePlan` → **采购方案成本测算规则**对比 `InitialPurchaseObjective` 相关成本。

**验收点**：输出是**采购建议/候选计划**而非已下达订单；无采购订单执行、发货、收货跟踪；可解释交期与成本权衡。

### 场景 S07｜上市风险

**时间 / 角色**：T-9（11/06，亦可演示 T-1 最终复核），上市项目负责人。

**主 Query**：`综合当前齐套进度、物料缺口及供应情况，上市计划存在哪些风险？能否按期上市？`

**示范系统回答**：

> 根据当前数据，历史风险包括：`LR-NP009-01` 商品发布（已关闭）、`LR-NP009-02` 配方冻结（已关闭）、`LR-NP009-03` 物料数量不足（已关闭）；当前需关注 `LR-NP009-04` **供应可用日期晚于需求日期（评估中）**。同时六类齐套中**供应 Q0004、门店与营销 Q0006 尚未齐套**。因此，**目前不能认定全部上市前保障条件已满足，尚不能直接给出可以顺利上市/允许放行的结论**。下一步应列出对应子项、影响、责任人、整改措施和复核条件。

**后台执行**：执行子齐套状态判断 → 汇总 `ReadinessUnit` 六域状态 → 关联 `LaunchRisk` 明细 → **新品上市前计划通过状态判断规则** → 展示有证据的放行建议；风险聚合、分级、自动关闭属于**建议新增**。

**验收点**：已关闭风险与当前阻断项分开显示；不为演示效果强行将计划改为“可上市”；责任人/整改动作只读源数据或规则结果，不杜撰。

## **三、演示成功标准**

观众应能从同一份 NP009 上市计划中，清楚看到：**计划与目标 → 六类齐套排期 → 当前齐套与物料缺口 → 首批采购方案 → 供应到货可行性 → 上市风险与放行结论**，并下钻到时间节点、触发规则及关联实体。每一项风险必须能够从总览追溯到子齐套和业务数据，而不仅是一个手工录入的风险标签。
