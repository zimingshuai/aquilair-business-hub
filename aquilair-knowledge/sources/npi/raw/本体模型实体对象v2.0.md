## 采购订单跟踪

#### 订单交货逾期检查规则

- **规则编码：**
- **规则描述：** 检查仍需履约的采购订单是否超过要求交货日期，识别当前逾期订单及未交货数量，提醒业务人员催交。
- **触发方式：** 自动触发、手动触发。自动触发包括每日定时检查，以及订单交货数量、要求交货日期变化后检查。
- **作用实体对象：** `PurchaseOrder`
- **规则逻辑：**
- **输入数据：**

  - 采购订单：`PurchaseOrder`
  - 主要字段：`required_delivery_date`、`undelivery_qty`、`current_overdue_days`、`cancel_flag`、`close_flag`。
- **处理逻辑：**

  - step1：筛选未取消、未关闭，且 `undelivery_qty > 0` 的采购订单。
  - step2：逾期天数大于0，判定为当前交货逾期。
  - step3：对逾期订单调用交货逾期通知动作，输出订单编号、物料、供应商、要求交货日期、未交货量和逾期天数。
- **输出结果**：输出当前交货逾期订单清单，并触发业务人员催交提醒。

#### 预计到达日期不满足要求交期的检查规则

- **规则编码：** 
- **规则描述：** 比较采购订单预计到达日期与要求交货日期，提前识别预计无法满足订单交期的采购供应。
- **触发方式：** 自动触发、手动触发。自动触发包括每日定时检查，以及预计到达日期、要求交货日期变化后检查。
- **作用实体对象：** `PurchaseOrder`
- **规则逻辑：**

  - **输入数据：**
  
    - 采购订单：`PurchaseOrder`
    - 主要字段：`estimated_arrival_date`、`required_delivery_date`、`expected_delay_days`、`undelivery_qty`、`cancel_flag`、`close_flag`。
  - **处理逻辑：**
  
    - step1：筛选未取消、未关闭，且 `undelivery_qty > 0` 的采购订单。
    - step2：若预计延期天数大于0，对预计延期订单调用预警通知动作，提示业务人员确认到货承诺、催货或协调加急。
    - step3：预计到达日期为空，或该日期已过但订单仍未交完时，输出“预计到达日期待确认”，不能判为正常保障。
  - **输出结果：** 输出订单交期预计满足情况、预计延期天数及异常原因，并对预计延期或到货时间待确认的订单发送通知。

#### 采购供应按时保障供需分配需求检查规则

- **规则编码：** 
- **规则描述：** 逐条检查采购在途分配，判断采购供应预计能否在物料需求日期前提供足够数量，识别不能按时保障的分配及缺口。
- **触发方式：** 自动触发、手动触发。自动触发包括每日定时检查，以及供应可用日期、供应数量、分配数量、需求日期或关联订单有效性变化后检查。
- **作用实体对象：** `SupplyDemandAllocation`  
**关联实体对象：** `PurchaseOrder`
- **规则逻辑：**

  - **输入数据：**
  
    - 供需分配：`SupplyDemandAllocation`
    - 采购订单：`PurchaseOrder`
    - 主要字段：`supply_type`、`allocation_status`、`supply_nr`、`demand_nr`、`supply_available_date`、`material_demand_date`、`supply_available_qty`、`allocated_qty`、`expected_supply_qty_ontime`、`expected_gap_qty`。
  - **处理逻辑：**
  
    - step1：筛选：
    - supply_type = PURCHASE_IN_TRANSIT  
    且 allocation_status = CONFIRMED  
    且 allocated_qty > 0
    - step2：通过 `supply_nr = PurchaseOrder.purchase_order_nr` 找到采购订单，采购订单的状态应该为未取消、未关闭。
    - step3：对有效采购供应，计算预计按时供应数量：
    - 如果 supply_available_date > material_demand_date：  
        expected_supply_qty_ontime = 0  
      
    否则：  
        expected_supply_qty_ontime  
            = MIN(supply_available_qty, allocated_qty)
    - step4：计算预计按时缺口：
    - expected_gap_qty  
        = MAX(0, allocated_qty - expected_supply_qty_ontime)
    - step5：`expected_gap_qty = 0` 时，判定本条分配预计能够按时保障；大于0时，判定预计不能完全保障，输出缺口及原因。
    - step6：关联订单已取消或关闭、不再承担剩余供应，但仍存在未履约分配时，输出供应失效预警，不能直接忽略这条分配。
  - **输出结果：** 输出分配编号、采购订单编号、需求编号、分配数量、预计按时供应数量、预计缺口量和原因；对不能保障的分配触发通知，并调用供需重算动作重新检查补位供应。
